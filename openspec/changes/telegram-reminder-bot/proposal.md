# Telegram 提醒机器人 - 需求提案

## 背景

为个人用户构建一个 Telegram 提醒机器人，支持通过自然语言设置各类提醒，帮助用户管理日程和待办事项。用户消息通过 AI 大模型进行自然语言解析，提取时间和提醒内容。

## 目标用户

个人用户，中文交互，固定时区（Asia/Shanghai）。

## 功能需求

### R1: 一次性定时提醒
- 用户发送自然语言消息，机器人通过 AI 大模型解析出时间和内容
- 示例："明天下午3点提醒我开会"、"2月14日提醒我送花"
- 到达指定时间后，机器人发送提醒消息给用户
- 用户可查看、取消已设置的提醒

### R2: 重复提醒（每日/每周/每月）
- 支持周期性提醒设置
- 示例："每天早上8点提醒我喝水"、"每周一提醒我写周报"、"每月1号提醒我交房租"
- 用户可暂停、恢复、删除重复提醒

### R3: 倒计时提醒
- 支持相对时间提醒
- 示例："30分钟后提醒我回电话"、"2小时后提醒我取快递"

### R4: 工作日提醒
- 仅在工作日（周一至周五）触发
- 排除周末，节假日处理为可选增强
- 示例："每个工作日早上9点提醒我打卡"

### R5: 提醒管理
- `/list` - 查看所有活跃提醒
- `/cancel <id>` - 取消指定提醒
- `/pause <id>` - 暂停重复提醒
- `/resume <id>` - 恢复重复提醒
- `/help` - 显示使用帮助

### R6: AI 大模型自然语言解析
- 每条用户消息发送至 AI 大模型进行意图识别和时间解析
- 大模型返回结构化 JSON，包含：提醒类型、触发时间、重复规则、提醒内容
- 解析失败时，机器人提示用户重新输入并给出示例
- 大模型需预设系统提示词，约束输出格式和行为

### R7: 大模型系统提示词
- 系统提示词需包含：
  - 角色定义：你是一个中文提醒助手，负责从用户消息中提取提醒信息
  - 当前时间注入：每次调用时动态注入当前时间（Asia/Shanghai）
  - 输出格式约束：必须返回严格的 JSON 格式
  - JSON 结构定义：
    ```json
    {
      "type": "once | daily | weekly | monthly | weekday | countdown",
      "time": "ISO 8601 格式的触发时间（一次性/倒计时）",
      "cron": "cron 表达式（重复类型）",
      "content": "提醒内容文本",
      "confidence": 0.0-1.0,
      "raw_time_text": "用户原始时间表述"
    }
    ```
  - 置信度阈值：confidence < 0.7 时视为解析失败
  - 边界处理：非提醒类消息返回 `{"type": "not_reminder"}`
  - 禁止编造：无法确定时间时返回解析失败而非猜测

## 技术约束

### C1: 技术栈
- 运行时：Node.js + TypeScript
- Telegram SDK：grammY 框架
- 数据库：SQLite（通过 better-sqlite3 或 drizzle-orm）
- 调度器：node-cron
- AI 大模型：硅基流动 API（https://api.siliconflow.cn/v1），兼容 OpenAI SDK 格式
- 部署：Docker 容器

### C2: 架构约束
- 单进程运行，无需分布式
- 数据持久化到 SQLite 文件
- 进程重启后能恢复所有未触发的提醒
- 时区固定为 Asia/Shanghai

### C3: AI 调用约束
- 使用 OpenAI 兼容的 SDK（openai 包），指向硅基流动 API 端点
- API Key 通过环境变量 `SILICONFLOW_API_KEY` 注入
- 每条用户消息均调用大模型（无预过滤）
- 大模型响应超时设置为 30 秒
- 调用失败时向用户返回友好错误提示，不暴露技术细节
- 系统提示词存储在代码常量中，便于维护和调整

### C4: 代码约束
- 不可变数据模式，禁止直接修改对象
- 小文件原则，单文件不超过 400 行
- 按功能/领域组织目录结构
- 完善的错误处理

### C5: 安全约束
- Bot Token 通过环境变量 `TELEGRAM_BOT_TOKEN` 注入
- AI API Key 通过环境变量 `SILICONFLOW_API_KEY` 注入
- 所有密钥禁止硬编码
- 用户输入必须验证和清理
- SQLite 使用参数化查询
- 大模型返回的 JSON 必须经过 schema 验证后才能使用

## 范围排除

- 不支持群组提醒（仅私聊）
- 不支持多语言（仅中文）
- 不支持多时区（固定 Asia/Shanghai）
- 不支持节假日日历（首版）
- 不支持 Web 管理界面
- 不支持多轮对话追问（解析失败直接提示重试）
- 不支持大模型流式输出（使用完整响应模式）

## 依赖

- Telegram Bot API（需要 Bot Token）
- 硅基流动 API（需要 API Key，兼容 OpenAI SDK）
- Node.js >= 18
- Docker（部署环境）
